# SoftSkill on Qwen3-8B: reproduction report (single-round, Table 1)

Reproduction of Tao et al., 2026, *SoftSkill: Behavioral Compression for Contextual Adaptation*
(arXiv 2606.20333) with the authors' code, changing only the target model from Qwen3.5-4B to
Qwen3-8B. Runs: 2026-10-05 22:17 → 2026-10-06 02:32 UTC. All numbers are from `logs/summary.json`
(generated by `scripts/summarize.py`).

**Short version**

- **SearchQA reproduces.** On Qwen3-8B, SoftSkill gets 74.2 ± 0.3 test-hard, compared with 71.7 for
  the SkillOpt hard skill and 67.9 with no skill. That is the same ordering as the paper, using 32
  soft tokens in place of a 1,995-token Markdown skill.
- **The LiveMath comparison is not valid as run.** With the upstream 16-token decoding budget,
  Qwen3-8B (non-thinking) starts writing out its reasoning on every question and gets cut off before
  it answers. So every untrained baseline scores 0.0, and so does the hard skill. SoftSkill's
  38.2 ± 4.0 is real, and well above chance (20%, 5 choices). But the gap to the baselines mostly
  shows that SoftSkill learned the `<answer>X</answer>` format. It does not show that a soft skill
  beats a hard skill at math. See [§6](#6-problems-and-things-that-look-suspicious).

### Data (verified split sizes)

| Task | Train / val / test | How it was built |
|---|---|---|
| SearchQA | 400 / 200 / 1,400 ✓ | Upstream `scripts/data/prepare_searchqa.py`, unchanged |
| LiveMath | 35 / 18 / 124 ✓ | `scripts/prepare_livemath_pinned.py` (see below) |

The upstream `prepare_livemath.py` re-splits *every* month currently on Hugging Face. The dataset has
grown since the paper, so it now gives 121/61/426, not the paper split. The adapter downloads only the
four files named in the released manifest, at its pinned revision. It then runs the upstream split
code and asserts the IDs match the manifest.

DocVQA is a vision task and can't run on text-only Qwen3-8B, so it was skipped. The optional LoRA
baseline was not run.

### Changes for Qwen3 (`patches/qwen3.patch`, 89 lines)

The upstream causal-LM wrapper is generic (`AutoModelForCausalLM` + `get_input_embeddings`), and
Qwen3-8B needed no model-class, tokenizer or chat-template changes. Only one change was required:

- **Opt-in gradient checkpointing** (`soft_prefix.gradient_checkpointing`, default `false`, so upstream
  behavior is unchanged unless the flag is set). At the upstream batch size of 8, Qwen3-8B runs out of
  memory on a 40 GB A100. The flag calls `gradient_checkpointing_enable(use_reentrant=False)` and, for
  the loss pass only, switches the frozen model to `train()`. Hugging Face only recomputes activations
  in train mode, and Qwen3 has no dropout, so the loss is unchanged. The flag is threaded through
  `SoftPrefixSettings` → `_build_prefix_model` → `SoftPrefixCausalLM`. The vision wrapper rejects it.
  All 24 upstream soft-prefix unit tests pass with and without the patch.

Our own adapters (no upstream edits):
- `scripts/run_with_hard_skill.py`: hard-skill baseline. It runs the upstream entry point as a
  no-skill evaluation, but writes the SkillOpt GPT-5.5 Markdown artifact into the system prompt's
  `## Skill` section exactly as the SkillOpt rollout does. `max_prompt_tokens` is raised from 2048 to
  8192 so the long skill never pushes the question out of the prompt.
- `scripts/run_one.sh`, `scripts/launch_all.sh`, `scripts/mirror_logs.sh`, `scripts/summarize.py`:
  launch, queue, mirror logs and aggregate results.

### Training and decoding (upstream values, unchanged)

| | SearchQA | LiveMath |
|---|---|---|
| Soft skill | p = p0 + Δp, 32 vectors × 4096, p0 = embeddings of the natural-language skill, backbone frozen | same |
| p0 source | `initial.md`, 21 tokens, tiled to 32 | `initial.md`, 202 tokens, first 32 used |
| Objective | NLL of `<answer>{gold}</answer><\|im_end\|>`, no chain-of-thought | same |
| Optimizer | AdamW, lr 1e-3, wd 0, batch 8, 3 epochs | same |
| Checkpoint selection | best of epochs 1–3 by val token-F1 (first 64 val items) | best of epochs 1–3 by val accuracy (all 18 items) |
| Decoding | greedy, max_new_tokens 64 | greedy, **max_new_tokens 16** |

(With weight decay 0, optimizing p directly from p0 gives the same result as optimizing Δp.)

### Timing

- SearchQA SoftSkill run: 35–44 min. Each training epoch (50 steps plus the 64-item validation) takes
  6–8 min, and the 1,400-item test evaluation takes most of the rest. SearchQA baselines: 19–29 min.
- LiveMath run (training or baseline): about 3 min.
- Whole queue (28 Qwen3-8B jobs on 2 GPUs): about 3 h 10 min.

| This run | **76.6** | 84.3 | 3 (val-hard 75.0 → 78.1 → 79.7) |

The harness reproduces the paper's number. One caveat: the check could not run with fully unchanged

| Method | Skill-context tokens | SearchQA | LiveMath |
|---|---|---|---|
| No skill | 0 | 67.9 (76.5) | 0.0 ⚠ |

## 4. What training adds

- **SearchQA:** init-only p0 is no better than no skill (66.9 / 67.7 vs 67.9). So the 32 starting
  vectors on their own carry nothing useful, and the whole gain of about 6 points comes from training.
  The gain is consistent: the 3 seeds fall within 1 point of each other.
- **Placement:** on SearchQA, prompt_start and skill_section are tied (74.2 vs 73.8, within about one
  std). On LiveMath, prompt_start is higher (38.2 vs 30.9). But with an 18-item validation set (one
  item = 5.6 points) and a spread of ±7.5 on skill_section, that gap isn't solid.

## 5. Comparison with the paper (Qwen3.5-4B)

| | Paper, Qwen3.5-4B | This repo, Qwen3-8B |
|---|---|---|
| SearchQA no skill | 68.1 | 67.9 |
| SearchQA SkillOpt (hard) | 71.2 | 71.7 |
| SearchQA SoftSkill | 76.4 | 74.2 (prompt_start) / 73.8 (skill_section) |
| LiveMath no skill | 22.4 | 0.0 ⚠ |
| LiveMath SkillOpt (hard) | 52.0 | 0.0 ⚠ |
| LiveMath SoftSkill | 50.0 prompt_start / 64.5 skill_section | 38.2 / 30.9 |

The models differ, so differences are expected.
- **SearchQA:** the baselines match the paper almost exactly. SoftSkill keeps a clear lead over the
  hard skill on Qwen3-8B, about 2.5 points against the paper's 5.2. So the main claim holds on a
  second model: a 32-vector soft skill can replace, and beat, a ~2k-token text skill.
- **LiveMath:** the comparison doesn't carry over. The paper reports nonzero baselines (22.4 and 52.0)
  with what we believe are the same harness and decoding settings. So it looks like Qwen3.5-4B in
  non-thinking mode answers immediately, while Qwen3-8B starts reasoning in prose. We have not
  confirmed this by running LiveMath on Qwen3.5-4B. The paper's finding that skill_section beats
  prompt_start on LiveMath (64.5 vs 50.0) is not reproduced: here the order is reversed, though
  within the noise.

## 6. Problems and things that look suspicious

1. **The LiveMath baselines are a truncation artifact, not a measurement.** The LiveMath system prompt
   says *"Think step by step, then provide your final answer inside `<answer>` tags"*, but decoding is
   capped at 16 tokens. On Qwen3-8B, the no-skill, hard-skill and init-only runs all start with text
   like `To determine which statement is **equivalent** to $H(n,m)^{\…` and hit the cap on 98–99% of
   items. The parser then gets no label, so the score is 0. The SoftSkill target has no reasoning
   (`<answer>X</answer>`), so the trained prefix learns to answer immediately (6.2 tokens on average).
   **Conclusion:** on LiveMath, "SoftSkill vs. baselines" here mostly measures format compliance
   under a 16-token budget. The 38.2 is still above chance (20%), so the soft skill encodes more than
   the format, but the run doesn't tell us how it compares with a hard skill. **Fix:** re-run the
   LiveMath baselines with a large `max_new_tokens` (e.g. 2048) as an extra, clearly labeled row, and
   keep 16 for the faithful-reproduction row.
2. **Two runs are missing:** LiveMath init-only seed 3 (prompt_start and skill_section). The root
   filesystem (`/`, shared, 547 GB) filled up at about 02:30. Python could not create a temporary
   file and crashed at import (`No usable temporary directory found`). About 440 GB of `/` belongs
   to directories this account can't read, i.e. other users. Our own data lives on `/data`. This
   commit makes `run_one.sh` set `TMPDIR` to `/data/a84460786/softskill_qwen3/tmp` so `/tmp` is no
   longer used. Both missing runs are init-only baselines that score 0.0 on seeds 1–2 for the reason
   in item 1, so none of the conclusions depend on them.
3. **`launch_all.sh` logged `rc=0` for the failed runs.** `$?` was read after `$(date)` had already
   reset it. Fixed in this commit, so the exit code is now captured first.
4. **LiveMath is small and noisy.** 18 validation items (one item = 5.6 points) choose the epoch, and
   124 test items give about ±4 points of sampling error. Seed spread is up to ±7.5.
5. **Not done:** the optional LoRA baseline, and DocVQA (not possible on a text-only model).

## 7. Reproducing

```bash
scripts/setup_env.sh            # venv under /data, applies patches/qwen3.patch to the submodule
scripts/prepare_data.sh         # official splits + skill artifacts under /data/.../data
nohup scripts/launch_all.sh "5 6" > /data/a84460786/softskill_qwen3/results/logs/launch_all.out 2>&1 &
```

Jobs whose `summary.json` already exists are skipped, so re-running `launch_all.sh` with a new queue
file only runs what's missing.
